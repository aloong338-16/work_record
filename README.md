# 工记 · 工作记录助手

一个**本地单文件**的工作记录工具：双击 `工作记录助手.html` 即可离线记录。可选的 AI 润色连接自己配置的接口；服务商限制浏览器跨域访问时，通过附带的本机转发服务连接。

## 功能

- **工作记录**：按天记录工作内容（项目、分类、状态、耗时），支持搜索、筛选、增删改查
- **周视图**：自动汇总一周记录，一键生成可复制的周报文字，支持自定义时间段浏览
- **月报**：按月汇总工作内容，生成适合粘贴到 PPT 的汇报文字，支持任意月份直选
- **多账号**：各账号注册登录，数据按账号完全隔离，可多人共用一份软件
- **个人分类**：内置 BUG 修复、需求分析、代码评审等分类；选择“其他”可手输分类，并选择是否保存到自己的账号
- **单文件迁移**：个人 JSON 包含账号、记录、分类、配置和草稿；新电脑可在登录页直接导入，无需先注册
- **主题**：亮色 / 暗色 / 跟随系统
- **AI 润色（可选）**：默认关闭，支持 Chat Completions / Responses、自动兼容接口路径、本机转发，以及获取模型列表后下拉选择

## 快速开始

```bash
git clone <仓库地址>
```

克隆后**直接双击打开 `工作记录助手.html`**。首次使用注册自己的账号；已有个人 JSON 时，在登录页直接导入或绑定，再使用原账号密码登录。

> 推荐用 Chrome / Edge 打开，并按软件内提示绑定本地数据文件，防止清理浏览器数据时丢失记录。

## 使用 AI

1. 首次在 Windows 上使用时，安装 Node.js 22 或更新版本，运行一次 `启动AI助手.cmd`。它会为当前 Windows 用户登记网页启动入口，启动本机服务并打开原 HTML；无需管理员权限或 npm 依赖。
2. 在设置中填写服务商的 Base URL 和 API Key，点击“获取模型”并下拉选择，也可直接手填模型名称。
3. 接口协议和连接方式保持“自动”即可；需要时可以指定 Responses 或 Chat Completions。点击“测试连接”，成功后开启 AI 开关并保存配置，再在周视图/月报中使用 AI 润色。

此后直接打开 HTML，在设置中点“启动 AI 服务”即可。如果获取模型、测试连接或润色时服务尚未运行，页面会提供“启动并继续”，启动后自动接着完成请求。浏览器第一次可能询问是否允许打开本机应用，需要允许。重启电脑后同样可从网页启动；移动项目目录或换电脑后，需要重新执行一次首次配置。

普通记录仍可直接双击 HTML 离线使用。支持浏览器跨域的接口也可以直连。转发服务只监听本机 `127.0.0.1:17654`，不保存 Key 或请求正文；Key 仍按原有方式保存在个人配置中。网页启动链接为固定的 `gongji-ai://start`，不携带 Key、地址或工作记录。关闭网页后服务仍在后台运行。Mac/Linux 可用 `node ai-bridge.mjs` 启动服务，再打开 HTML；网页唤起功能目前适用于 Windows。

移除当前用户的网页启动入口：在项目目录运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\register-ai.ps1 -Uninstall`。这只移除启动入口，不处理个人 JSON 或浏览器数据。

## 数据说明（重要）

- 注册后默认写入当前浏览器的本地存储 `gongji_blob_v1`，不会自行在仓库旁创建文件；只有创建或绑定 JSON 后，才会自动写入你选定的文件
- 新建的数据文件和导出的个人 JSON 只包含当前账号的密码校验信息、记录、分类、配置和草稿，不包含其他本机账号，也不保存明文登录密码
- **仓库里不包含任何人的数据**；`work_data/` 等数据目录已在 `.gitignore` 中排除，请勿手动提交
- AI 的 URL、API Key 和模型配置保存在浏览器本地存储中，也会随个人 JSON 保存或导出，不会改写进 HTML 或转发服务代码。个人 JSON、`work_data/`、`.env` 和常见私钥文件均被 Git 忽略；请勿使用强制添加绕过忽略规则
- 推荐把个人 JSON 放在仓库外的固定目录；放在仓库内时使用 `work_data/`。JSON 和 JSON 备份文件默认被 Git 忽略，更新代码不需要移动个人配置
- 换电脑 / 换浏览器：在新设备登录页导入或绑定这一个 JSON，之后使用原账号密码登录，无需另外携带账号文件
- 同步盘中的文件由同步盘客户端传输；本工具在登录、回到窗口、前台每 30 秒和写入前与绑定文件合并。也可以在设置中点“立即同步”。两台电脑建议轮流使用并等文件同步完成，适合个人记录，不提供多人同时编辑的原子事务保证

## 零服务器同步

最省事的是使用已经在用的同步盘，把个人 JSON 放在其同步目录，两台电脑各绑定各自目录里的同一份文件。本工具不需要服务器或数据库服务。若没有同步盘，也可使用免费的开源 Syncthing 在自己的设备之间同步数据目录；设备需要建立连接才能传输更新，网页本身不承担跨电脑传输。

同一条记录的修改按更新时间合并，删除操作带有删除标记，个人配置和草稿按各自更新时间合并。设备系统时间应保持准确。同步软件生成冲突副本时，可先保留两份文件，再通过“合并导入”恢复其中的记录。

详细用法见 [使用说明.md](使用说明.md)。

## 目录结构

```
├── 工作记录助手.html   # 软件本体（单文件，包含全部功能）
├── 启动AI助手.cmd      # Windows AI 启动入口
├── start-ai.ps1        # 启动并检查本机服务、打开原 HTML
├── register-ai.ps1     # Windows 当前用户的网页启动入口
├── ai-bridge.mjs       # 本机 AI 转发（Node.js，无第三方依赖）
├── 使用说明.md         # 详细使用说明
├── tests/regression.mjs # 浏览器回归检查
└── work_data/          # 本地数据文件（git 忽略，不上传）
```

## 回归检查

安装 Node.js 22 或更新版本，并使用本机 Chrome 或 Edge，运行：

```bash
node tests/regression.mjs
node --test tests/ai-bridge.test.mjs
```

`tests/` 是供维护者验证软件功能的代码，可以公开上传 Git，日常使用无需运行。检查使用独立的临时浏览器和测试数据，结束后自动清理，不会读取或修改日常使用的数据。覆盖空周报/月报、记录增删改、草稿、自定义分类、账号与文件绑定隔离、登录前导入、跨电脑恢复、同步合并和备份导入导出。AI 检查使用不开放 CORS 的模拟接口，覆盖文件页面转发、模型列表、两种协议、SSE 回复、路径兼容、鉴权错误、网页启动后继续请求，以及周报/月报润色。文件选择器和系统唤起使用模拟接口；导出会实际下载并校验 JSON 文件。浏览器不在常见位置时，可用 `GONGJI_BROWSER_PATH` 指定浏览器程序路径。

需要验证自己的真实接口时，可运行 `node tests/ai-live.mjs <个人JSON路径> [auto|chat|responses]`。这个可选检查只读取指定文件，获取模型并发送一句简短测试提示，可能产生服务商调用费用，不会输出 Key 或发送工作记录。
